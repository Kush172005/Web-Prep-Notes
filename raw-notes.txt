**Deep Copy**

The combination of `JSON.stringify()` and `JSON.parse()` can create a deep copy of an object in a simple way by leveraging JSON's inherent structure. Here's a breakdown of how this works:

Deep Copy → `JSON.parse(JSON.stringify(original))`

Shallow Copy →  . . . original   `Spread Operator` 

### 1. **`JSON.stringify()`**:

- **What it does**: Converts a JavaScript object into a JSON string.
- **How it works**: When you pass an object to `JSON.stringify()`, it recursively converts each property and nested object of the object into a string representation. It turns the object into a plain string format like this:

```jsx

const obj = { name: "John", address: { city: "New York" } };
const jsonString = JSON.stringify(obj);
console.log(jsonString); // '{"name":"John","address":{"city":"New York"}}'
```

### 2. **`JSON.parse()`**:

- **What it does**: Converts a JSON string back into a JavaScript object.
- **How it works**: When you pass the JSON string returned by `JSON.stringify()` to `JSON.parse()`, it reconstructs the original object from the string, but it's important to note that this creates a *new* object, not just a reference to the original one.

```jsx
const newObj = JSON.parse(jsonString);
console.log(newObj); // { name: "John", address: { city: "New York" } }
```

### Why it works for deep copying:

1. **Cloning by Value**: When you convert an object to a string with `JSON.stringify()`, all nested properties are converted to string representations as well. This means the entire object, including nested structures, is fully serialized into a string. When you parse this string with `JSON.parse()`, the entire object structure is rebuilt from scratch, ensuring that the new object is independent of the original.
2. **No Shared References**: Since the `JSON.parse()` function creates a new object from the string and all the nested objects are serialized and then recreated, there are no references to the original objects. This means changes made to the new object won’t affect the original object, and vice versa.

**Event delegation** is a technique in JavaScript where instead of attaching event listeners to individual child elements, a single event listener is attached to a parent element to handle events for all child elements.

- **Event Bubbling**: The event propagates from the target element up through the parent elements.
- **Event Capturing**: The event propagates from the root element down to the target element

In simple terms, **method invocation** in JavaScript is when you call a function that is attached to an object (this function is known as a method). When a method is invoked, the `this` keyword inside the method refers to the object it belongs to. This allows the method to access and manipulate the object’s properties.

- `call()` is a method that allows you to invoke a function and explicitly set the value of `this`. You can also pass arguments one by one.
- `apply()` is similar to `call()`, but instead of passing arguments one by one, you pass them as an array.
- `bind()` doesn’t immediately invoke the function. Instead, it creates a new function with the `this` context and any preset arguments that you provide, and you can call it later

### **This**

In JavaScript, `this` refers to the context in which a function is called. It represents the object that is currently executing the code. **Explicitly setting the value of `this`** means that you are manually defining what `this` should refer to within a function, rather than letting JavaScript decide automatically based on how the function is called

### **DOM (Document Object Model)**

**DOM** is a structured representation of the HTML elements that are present in a webpage or web app. DOM represents the entire UI of your application. The DOM is represented as a tree data structure. It contains a node for each UI element present in the web document.

### **Virtual DOM**

The **Virtual DOM (VDOM)** is a lightweight, in-memory representation of the actual DOM

**Virtual DOM** is a programming concept where a "virtual" representation of a UI is kept in memory and synced with the "real" DOM by a library such as ReactDOM. This process is called reconciliation. The Virtual DOM enables React to update only the parts of the DOM that need to be updated, rather than re-rendering the entire page.

### Reconciliation

In the context of React, **reconciliation** is the process through which React updates the actual DOM to match the virtual DOM when changes occur. It involves identifying which elements in the virtual DOM have changed and efficiently updating only those parts in the real DOM.
